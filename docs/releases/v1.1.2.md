## Magyar

### Javítás: megálló lejátszás Windows-szerveren (1.1.2)
- Windowson a lejátszás pár percenként megállhatott, remuxnál is, és csak kilépés és újraindítás segített. Ennek oka, hogy a szerver olvasás közben zárolta az ffmpeg HLS-lejátszási listáját, így az ffmpeg nem tudta lecserélni. Most a szerver úgy olvassa a listát, hogy közben az ffmpeg lecserélheti.

### Biztonság
- A kezdő beállítás (az első admin fiók) csak a helyi hálózatról, loopbackről vagy Tailscale-ről végezhető el; `KINORA_ALLOW_REMOTE_SETUP=1` feloldja. A beállító oldal előre elmagyarázza, ha innen nem lehet.

### Több mappás médiakönyvtár
- Egy könyvtár több mappát is tartalmazhat (például több lemezen lévő filmeket): az admin párbeszédablakban mappánként egy sor és „mappa hozzáadása”. Ha egy mappa nem érhető el vagy hirtelen üres, a beolvasás leáll, és semmit nem jelöl hiányzónak. A letöltések az első mappába kerülnek.

### Egyéb javítások
- iOS: a letöltések Live Activityje helyesen számolja a kész és sikertelen letöltéseket, egy új letöltéskör lecseréli az előző összesítőt, és a szerveroldali előkészítés vége azonnal frissíti a zárolási képernyőt.
- Jellyfin-kompatibilis API: a hallássérülteknek szóló feliratok jelölése megmarad az újraolvasások után is, és a Jellyfin-kliensek is látják.

## English

### Fix: playback stopping on a Windows server (1.1.2)
- On Windows, playback could stop every few minutes, remux included, and only leaving and restarting helped. The cause: the server locked ffmpeg's HLS playlist while reading it, so ffmpeg could not replace it. The server now reads the playlist in a way that lets ffmpeg replace it meanwhile.

### Security
- The initial setup (the first admin account) is accepted only from the local network, loopback or Tailscale; `KINORA_ALLOW_REMOTE_SETUP=1` lifts this. The setup page explains it up front when it applies.

### Libraries with several folders
- A library can span several folders (films on more than one disk, for example): the admin dialog lists one row per folder with "add folder". A folder that is unavailable or suddenly empty still aborts the scan without marking anything missing. Downloads are imported into the first folder.

### Other fixes
- iOS: the downloads Live Activity counts finished and failed downloads correctly, a new run replaces the previous summary, and the end of the server-side preparing phase updates the lock screen at once.
- Jellyfin-compatible API: the hearing-impaired flag of subtitles survives rescans and is shown to Jellyfin clients.
